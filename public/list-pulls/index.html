Demandbase Person List Pull
Standard operating procedure — contact extraction from named account sets using Advanced selector mode
Workspace: US + Global (dual)
List Type: Dynamic
Selector Mode: Advanced
Tenant: 15053
Updated: April 2026
Process — 5 Steps

End-to-End Workflow

Follow this sequence every time. Workspace first, selectors second, export third.

⚠️ CRITICAL: US Workspace First — ALWAYS Build all lists in US Workspace, then duplicate to Global with [US] prefix. Never build in Global first. No sync exists between workspaces — both must be maintained manually.
01
Workspace — Start in US Workspace (Non-Negotiable)
Navigate to Database → People Lists inside US Workspace — this is the only approved starting point. Build and save your list here first. Once complete, duplicate it to Global Workspace and immediately remove the Copy of — prefix so naming stays clean across both environments. IMPORTANT: No sync exists between workspaces — both must be maintained manually. If this list feeds an advertising campaign, the Global version must carry the [US] prefix (TP Rule #2: Advertising campaigns only read from Global).
02
Create New List — Set Type to Dynamic
Select New Person List and set the type to Dynamic. Dynamic lists auto-refresh as contacts sync from SFDC — correct for any ongoing outreach or campaign motion. Static lists are point-in-time only and go stale quickly.
03
Switch to Advanced Selector Mode — Stack Filters in Order
Click Advanced in the selector panel. Apply all Required and Critical filters first — these are non-negotiable on every list. Optional filters sharpen targeting further when you know the tier or buying group scope. See the Selector Reference table below for the full filter set, correct operators, and what each one does.
04
Export and Format for Intake
Run the list and export. Format the output to match the intake field requirements before submitting — clean column headers, no extra rows, no raw Demandbase export formatting. This route bypasses the standard campaign build request queue and the SLA attached to it. The intake form is the handoff.
05
Submit Intake Form
Submit the intake form with the formatted export attached. If this motion escalates into a sequenced campaign with landing pages or form fills, flag it as a separate request — SFDC program sync and attribution writeback must be wired before launch or those touches will not appear in the pipeline record.

🌎
Why There Is No Separate Country Filter
Industry Category contains "US Market" handles geographic scoping by design. That tag is applied only to US-scoped accounts in the account universe — it excludes all non-US geographies automatically. Adding a separate Country field is redundant and introduces over-filtering risk if SFDC country data is inconsistently populated. Tiering + US Market tag is the complete and correct scoping method.
📧
Why Email Opt-Out Is NOT Part of the Selector Logic
Marketo handles opt-out suppression automatically when the list goes through email deployment — it catches unsubscribes before anything sends. Adding Email Opt-Out = False at the Demandbase layer is redundant for email motions and problematic for everything else. The person list is a data asset used for call-down, BD outreach, event invites, and SDR sequences — all valid uses where opted-out contacts are perfectly reachable by phone or other channels. Baking opt-out suppression into the list build quietly removes contacts you'd never know were excluded, and neither would the SDR making the calls.
🔄
Dual Workspace Maintenance — Non-Negotiable
No sync exists between US Workspace and Global. Build in US Workspace first, duplicate to Global, remove Copy of — immediately. If the list feeds an ad campaign, the Global version requires the [US] prefix to signal US ownership and prevent EMEA from touching it. Both versions require manual updates whenever the account set or filter criteria changes.
✅
Know Your Motion Type Before You Export
A direct send from an exported list works cleanly for a one-touch outreach motion — no additional infrastructure needed. The moment it becomes sequenced with landing pages or form fills, attribution goes dark without Marketo program sync and SFDC campaign member writeback. Flag sequenced motions before the first send, not after.

Routing Reference

What Happens After Export

The list pull is the beginning. Where the contact goes depends on tier and motion type.

⚠️
Do Not Filter by MQA Qualified
The Is MQA Qualified and Is MQA Qualified — US Journey fields are not routing signals. Both return false on accounts with 60+ US CX Pipeline Predict scores — confirmed live on BFS pulls (Morgan Stanley, Freddie Mac). Route on tier + scoring stack: US CX Pipeline Predict, US Qualification Score, US Vertical CX Score, and engagement (3 Months / 7 Days). Thresholds: 40–59 → SDR, 60+ → BD. If you filter on MQA Qualified, your export will return a fraction of what is actually in-market.
Tier 1A + Tier 1
Route to BD
High-priority accounts. Export goes to the BD team for direct outreach coordination. Do not put Tier 1A contacts into an SDR sequence — these accounts require a senior-touch motion, not automated cadence.
Tier 2 + Tier 3
Route to SDR
Mid and lower-tier accounts go into SDR sequence workflow via intake form. Formatted output must match sequence tool field mapping — confirm column headers before submitting.
One-Touch Send
Direct Export — No Attribution Wire Needed
Single direct send with no landing page or form fill — export and send. Attribution is not trackable through this path. That is an accepted and intentional trade-off for speed-to-send.
Sequenced Campaign
Flag Before Launch
Any motion with landing pages, form fills, or multi-touch nurture requires Marketo program sync and SFDC campaign member writeback to be wired first. Flag it as a separate request before the first send — not after.
